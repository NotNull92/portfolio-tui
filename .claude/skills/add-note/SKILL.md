# NOTES 서가에 글 추가하기

사용자가 글을 주면 **파일 하나를 새로 만드는 것**이 전부다.
`src/data/notes.js` 는 로더일 뿐이므로 절대 건드리지 않는다.

## 절차

### 1. 글을 읽고 분류를 판단한다

사용자가 분류를 지정하지 않았다면 내용을 읽고 정한다.

| type | 언제 |
|---|---|
| `POEM` | 행갈이가 의미를 갖는 글, 운율·이미지 중심, 짧고 함축적 |
| `ARTICLE` | 주제를 설명·논증하는 글. 개발 회고, 기술 에세이, 분석 |
| `PHILOSOPHY` | 존재·가치·의미에 대한 사유. 결론보다 물음이 중심 |
| `THOUGHT` | 위 어디에도 딱 안 맞는 짧은 단상·메모. 애매하면 여기 |

애매하면 사용자에게 묻지 말고 `THOUGHT` 로 두되, 최종 보고에서
"이렇게 분류했다"고 밝혀 사용자가 바로잡을 수 있게 한다.

### 2. 제목·날짜·발췌를 정한다

- **제목**: 사용자가 준 제목을 그대로 쓴다. 없으면 본문에서 뽑되,
  창작하지 말고 본문에 실제로 있는 표현을 쓴다.
- **날짜**: 오늘 날짜(`YYYY-MM-DD`). 사용자가 다른 날짜를 지정하면 그것을 쓴다.
- **발췌(excerpt)**: 목록에 뜨는 한 줄. 40자 안팎.
  본문의 핵심 문장을 그대로 따오는 편이 낫다. 마땅치 않으면
  frontmatter 에서 `excerpt` 를 아예 빼면 첫 문단에서 자동 생성된다.

### 3. 파일을 만든다

경로: `src/content/notes/YYYY-MM-DD-제목.md`

파일명의 제목 부분은 공백을 `-` 로 바꾼다. 한글 그대로 써도 된다.
같은 날짜에 이미 파일이 있어도 제목이 다르면 충돌하지 않는다.

```markdown
---
title: 글 제목
type: POEM
date: 2026-08-08
excerpt: 목록에 보일 한 줄
---

본문 첫 문단.

빈 줄 하나가 문단 구분이다.
```

### 4. 본문을 옮길 때

- **사용자의 문장을 고치지 않는다.** 오탈자로 보이는 것도 임의로 손대지 않는다.
  고칠 만한 게 보이면 파일은 원문대로 만들고, 보고할 때 따로 언급한다.
- 문단(연) 사이는 **빈 줄 하나**로 맞춘다. 원문에 빈 줄이 여러 개면 하나로 줄인다.
- **시(`POEM`)는 원문의 줄바꿈을 그대로 둔다.** 뷰어가 `type: POEM` 일 때만
  `white-space: pre-line` 으로 행갈이를 살리므로, 각 행 끝에 공백 2칸을
  넣는 등의 마크다운 트릭을 쓸 필요가 없다.
  → 반대로 **산문은 하드랩하지 않는다.** 한 문단은 한 줄로 이어 쓴다.
- frontmatter 값에 `:` 가 들어가면 따옴표로 감싼다.

### 5. 검증한다

```bash
npm run lint && npm run build
```

빌드가 통과해도 실제로 떠야 확인이 끝난 것이다. 개발 서버가 떠 있으면
브라우저에서 NOTES 탭을 열어 다음을 확인한다.

- 새 글이 목록 **맨 위**에 있는가 (날짜 내림차순 정렬)
- 분류 배지 색과 라벨이 맞는가
- 책을 열었을 때 본문이 잘리거나 깨지지 않는가
- 여러 장이면 페이지 넘김이 되는가

### 6. 커밋한다

사용자가 요청했을 때만 커밋·푸시한다.
커밋 메시지는 한국어로, 어떤 글을 왜 그 분류로 넣었는지 한 줄 남긴다.

```
content(notes): '글 제목' 추가 (POEM)
```

## 하지 말 것

- `src/data/notes.js` 수정 — 로더다. 글을 추가할 때 손댈 일이 없다.
- 기존 `.md` 파일 수정 — 새 글 추가는 새 파일을 만드는 일이다.
- 사용자 문장을 다듬거나 요약하기 — 원문 그대로 옮긴다.
- 사용자가 주지 않은 내용을 지어내기 — 제목·발췌도 본문에서 가져온다.

## 참고

  **본문에 조작법을 쓰지 않는다.**
